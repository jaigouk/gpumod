### 1. `queue/core.py`
Contains the fundamental data structures and the basic FIFO (First-In-First-Out) queue.

```python
from dataclasses import dataclass, field
from typing import Callable, Any, List, Optional
from collections import deque

@dataclass
class Job:
    """Represents a unit of work to be processed."""
    id: str
    action: Callable
    args: tuple = field(default_factory=tuple)
    kwargs: dict = field(default_factory=dict)
    priority: int = 0
    retries: int = 0
    max_retries: int = 3

class JobQueue:
    """A basic FIFO queue for jobs."""
    def __init__(self):
        self._queue: deque[Job] = deque()

    def push(self, job: Job) -> None:
        self._queue.append(job)

    def pop(self) -> Optional[Job]:
        return self._queue.popleft() if self._queue else None

    def __len__(self) -> int:
        return len(self._queue)
```

### 2. `queue/retry.py`
 Isolates the logic for handling failures and calculating delays.

```python
import time
import random
from typing import Callable, Any
from .core import Job

def execute_with_retry(job: Job, base_delay: float = 1.0) -> Any:
    """
    Executes a job with exponential backoff.
    Formula: delay = base_delay * (2 ^ attempt) + jitter
    """
    attempts = 0
    while attempts <= job.max_retries:
        try:
            return job.action(*job.args, **job.kwargs)
        except Exception as e:
            attempts += 1
            if attempts > job.max_retries:
                print(f"Job {job.id} failed after {job.max_retries} retries.")
                raise e
            
            # Exponential backoff calculation
            delay = base_delay * (2 ** (attempts - 1))
            jitter = random.uniform(0, 0.1 * delay)
            
            print(f"Job {job.id} failed (Attempt {attempts}). Retrying in {delay:.2f}s...")
            time.sleep(delay + jitter)
```

### 3. `queue/priority.py`
 Specialized implementation for ordered processing.

```python
import heapq
from typing import Optional
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """
    A queue where jobs are processed based on priority.
    Lower priority numbers are processed first (e.g., 0 is higher than 10).
    """
    def __init__(self):
        # We use a list to support heapq operations
        self._heap: List[tuple[int, Job]] = []

    def push(self, job: Job) -> None:
        # heapq uses a min-heap by default
        heapq.heappush(self._heap, (job.priority, job))

    def pop(self) -> Optional[Job]:
        if not self._heap:
            return None
        # Return only the Job object, discarding the priority integer
        return heapq.heappop(self._heap)[1]

    def __len__(self) -> int:
        return len(self._heap)
```

### How to use the refactored package:
You can now use the library much more cleanly. Because of the `__init__.py` file, the user doesn't need to know the internal file structure.

```python
from queue import Job, PriorityQueue, execute_with_retry

def send_email(recipient: str):
    print(f"Sending email to {recipient}...")
    # Simulate a failure for retry demonstration
    raise ValueError("SMTP Server Down")

# 1. Create jobs
job1 = Job(id="1", action=send_email, args=("user1@test.com",), priority=10)
job2 = Job(id="2", action=send_email, args=("admin@test.com",), priority=1)

# 2. Use Priority Queue
pq = PriorityQueue()
pq.push(job1)
pq.push(job2)

# 3. Process (Notice job2 comes out first because priority 1 < 10)
while len(pq) > 0:
    current_job = pq.pop()
    try:
        execute_with_retry(current_job)
    except Exception:
        pass
```

### Key Improvements Made:
1.  **Encapsulation**: `JobQueue` doesn't need to know how `PriorityQueue` sorts items; it just provides the base interface.
2.  **Separation of Concerns**: If you want to change your retry logic (e.g., to Linear backoff instead of Exponential), you only modify `retry.py`.
3.  **Complexity**: `PriorityQueue` now uses `heapq` (O(log n)) instead of sorting a list every time (O(n log n)), making it much faster for large queues.
4.  **Namespace Management**: By using `__init__.py`, you prevent internal implementation details from leaking into the user's global namespace.
