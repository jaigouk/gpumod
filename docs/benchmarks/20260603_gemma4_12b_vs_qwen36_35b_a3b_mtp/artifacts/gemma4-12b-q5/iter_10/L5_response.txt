### The New Structure

```text
queue/
├── __init__.py      # Exports: JobQueue, Job, PriorityQueue, process_with_retry
├── core.py          # Job dataclass, basic queue operations
├── retry.py         # Retry logic with exponential backoff
└── priority.py      # Priority queue implementation
```

### 1. `queue/core.py`
This module defines the base data structures.

```python
from dataclasses import dataclass, field
from typing import Any, List, Optional

@dataclass(order=False)
class Job:
    """Basic Job unit of work."""
    id: str
    payload: Any
    priority: int = 0

    # We define __lt__ so PriorityQueue (heapq) knows how to compare jobs
    def __lt__(self, other: 'Job'):
        return self.priority < other.priority

class JobQueue:
    """A basic FIFO (First-In-First-Out) queue implementation. """
    def __init__(self):
        self._items: List[Job] = []

    def push(self, job: Job) -> None:
        self._items.append(job)

    def pop(self) -> Optional[Job]:
        return self._items.pop(0) if self._items else None

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
This module specializes the queue logic using a heap.

```python
import heapq
from typing import Optional
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """A Priority Queue implementation using a min-heap."""
    def __init__(self):
        # We don't use the list from JobQueue because heapq requires 
        # a specific structure, but we keep the inheritance for API consistency
        self._items: list[tuple[int, Job]] = []

    def push(self, job: Job) -> None:
        # Store as tuple (priority, Job) so heapq sorts by priority
        heapq.heappush(self._items, (job.priority, job))

    def pop(self) -> Optional[Job]:
        if not self._items:
            return None
        _, job = heapq.heappop(self._items)
        return job

    def __len__(self) -> int:
        return len(self._items)
```

### 3. `queue/retry.py`
This module handles the execution logic and error handling.

```python
import time
import logging
from typing import Callable, Any
from .core import Job

logger = logging.getLogger(__name__)

def process_with_retry(
    job: Job, 
    worker_func: Callable[[Job], Any], 
    max_retries: int = 3,
    base_delay: float = 1.0
) -> bool:
    """
    Executes a worker function with exponential backoff.
    Formula: delay = base_delay * (2 ** attempt)
    """
    for attempt in range(max_retries + 1):
        try:
            worker_func(job)
            return True
        except Exception as e:
            if attempt == max_retries:
                logger.error(f"Job {job.id} failed after {max_retries} retries: {e}")
                return False
            
            delay = base_delay * (2 ** attempt)
            logger.warning(f"Job {job.id} failed (attempt {attempt+1}). Retrying in {delay}s...")
            time.sleep(delay)
    return False
```

### Key Improvements Explained:

1.  **Encapsulation**: `core.py` handles the data definitions. If you decide to change `Job` from a dataclass to a dictionary later, you only have to change one file.
2.  **Inheritance vs Composition**: `PriorityQueue` inherits from `JobQueue`. This ensures that if you add a method like `.size()` to `JobQueue` in the future, `PriorityQueue` gets it automatically.
3.  **Namespace Management**: By importing everything into `__init__.py`, the user can still use the library simply:
    ```python
    from queue import Job, PriorityQueue, process_with_retry
    ```
    This hides the internal file structure from the end-user while keeping the code organized for the developer.
4.  **Complexity Separation**: The `retry.py` logic is completely decoupled from the `Queue` storage logic. You can now test the retry logic in isolation without needing to instantiate a complex queue.
