Here is the refactored package structure.

### 1. `queue/core.py`
Contains the base data structures and the basic queue logic.

```python
from dataclasses import dataclass, field
from typing import List, Optional, Any

@dataclass(order=False)
class Job:
    """Represents a unit of work in the system."""
    id: str
    payload: dict[str, Any]
    priority: int = 0

class JobQueue:
    """A basic First-In-First-Out (FIFO) queue."""
    def __init__(self):
        self._items: List[Job] = []

    def push(self, job: Job) -> None:
        self._items.append(job)

    def pop(self) -> Optional[Job]:
        if not self._items:
            return None
        return self._items.pop(0)

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
 Contains specialized logic for priority-based ordering.

```python
import heapq
from typing import Optional
from .core import Job

class PriorityQueue:
    """A priority queue where jobs with lower priority numbers are processed first."""
    def __init__(self):
        # We store tuples of (priority, index, job) 
        # to handle items with same priority correctly
        self._items: list[tuple[int, int, Job]]] = []
        self._counter = 0

    def push(self, job: Job) -> None:
        heapq.heappush(self._items, (job.priority, self._counter, job))
        self._counter += 1

    def pop(self) -> Optional[Job]:
        if not self._items:
            return None
        return heapq.heappop(self._items)[2]

    def __len__(self) -> int:
        return len(self._items)
```

### 3. `queue/retry.py`
 Contains the execution logic and error handling.

```python
import time
import logging
from .core import Job

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def process_with_retry(job: Job, max_retries: int = 3, base_delay: float = 1.0) -> bool:
    """
    Executes a job with exponential backoff.
    Returns True if successful, False otherwise.
    """
    for attempt in count in range(max_retries):
        try:
            logger.info(f"Processing job {job.id} (Attempt {attempt + 1})")
            # Simulated Work
            if "fail" in job.payload:
                raise ValueError("Simulated failure")
            
            logger.info(f"Successfully completed job {job.id}")
            return True
            
        except Exception as e:
            logger.warning(f"Attempt {attempt + 1} failed for job {job.id}: {e}")
            if attempt < max_retries - 1:
                sleep_time = base_delay * (2 ** attempt)
                time.sleep(sleep_time)
            else:
                logger.error(f"Job {job.id} failed after {max_retries} attempts.")
                
    return False
```

### 4. `queue/__init__.py`
 Exposes the public API so users can import directly from `queue`.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue
from .retry import process_with_retry

__all__ = [
    "Job",
    "JobQueue",
    "PriorityQueue",
    "process_with_retry",
]
```

### Key Refactoring Improvements:

1.  **Encapsulation**: `JobQueue` and `PriorityQueue` no longer share the same namespace. If you want to change how priority works (e.g., switching from `heapq` to a different algorithm), you only touch `priority.py`.
2.  **Relative Imports**: By using `from .core import ...`, the package remains portable. You can move the entire `queue/` folder anywhere in your project and the internal links won't break.
3.  **Namespace Management**: By defining `__all__` in `__init__.py`, you control exactly what is visible when a user types `from queue import *`.
4.  **Scalability**: If you need to add a new type of queue (e.g., `TimedQueue`), you simply create `timed.py` and add one line to `__init__.py`.
5.  **Readability**: The logic for "how to retry" (Infrastructure) is now strictly separated from the logic of "how to store jobs" (Data Structures).
