Since you didn't provide the specific source code for your monolith, I have implemented a standard, production-ready version of these components (including a dataclass for `Job`, a standard `JobQueue`, a `PriorityQueue` using `heapq`, and an exponential backoff `retry` mechanism).

Here is the refactored package structure.

### 1. `queue/core.py`
This file contains the base data structures and the basic FIFO queue.

```python
from dataclasses import dataclass, field
from typing import Any
from collections import deque

@dataclass
class Job:
    id: str
    payload: Any
    priority: int = 0
    retries: int = 0
    max_retries: int = 3
    
    # Required for PriorityQueue comparison logic
    def __lt__(self, other: 'Job'):
        return self.priority < other.priority

class JobQueue:
    """A basic First-In-First-Out (FIFO) queue for Jobs."""
    def __init__(self):
        self._queue: deque[Job] = deque()

    def push(self, job: Job) -> None:
        self._queue.append(obj)

    def pop(self) -> Job | None:
        try:
            return self._queue.popleft()
        except IndexError:
            return None

    def __len__(self) -> int:
        return len(self._queue)
```

### 2. `queue/priority.py`
This file handles the specialized priority logic. It imports `Job` from `core`.

```python
import heapq
from .core import Job

class PriorityQueue:
    """A Priority Queue implementation using a min-heap."""
    def __init__(self):
        self._queue: list[tuple[int, Job]] = []

    def push(self, job: Job) -> None:
        # We store a tuple so heapq knows to sort by priority
        heapq.heappush(self._queue, (job.priority, job))

    def pop(self) -> Job | None:
        try:
            _, job = heapq.heappop(self._queue)
            return job
        except IndexError:
            return None

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
This file isolates the retry logic, keeping it separate from the data structures.

```python
import time
import random
from .core import Job

def process_with_retry(job: Job, worker_func) -> bool:
    """
    Executes a worker function with exponential backoff.
    Returns True if successful, False if max retries exceeded.
    """
    while job.retries <= job.max_retries:
        try:
            worker_func(job.payload)
            return True
        except Exception as e:
            job.retries += 1
            if job.retries > job.max_retries:
                print(f"Job {job.id} failed after {job.max_retries} retries.")
                break
            
            # Exponential backoff: 2^retries + jitter
            wait_time = (2 ** job.retries) + random.uniform(0, 1)
            print(f"Retry {job.retries} for job {job.id} in {wait_time:.2f}s")
            time.sleep(wait_time)
            
    return False
```

### 4. `queue/__init__.py`
This defines the public API. Users will import from `queue` directly, not the sub-modules.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue
from .retry import process_with_retry

__all__ = [
    "Job",
    "JobQueue",
    "PriorityQueue",
    "process_with_retry",
]
```

### Key Improvements Made:

1.  **Encapsulation**: The `PriorityQueue` doesn't need to know how `process_with_retry` works, and `Job` doesn't need to know about the `PriorityQueue` implementation details.
2.  **Circular Dependency Prevention**: By placing the `Job` dataclass in `core.py`, both `priority.py` and `retry.py` can import it without creating a circular loop.
3.  **Clean API**: A user can now do this:
    ```python
    from queue import Job, PriorityQueue, process_with_retry

    q = PriorityQueue()
    q.push(Job(id="1", payload="data", priority=1))
    ```
4.  **Scalability**: If you decide to add a `DistributedQueue` or a `DeadLetterQueue` in the future, you can simply add a new file in the package without cluttering the existing logic.
