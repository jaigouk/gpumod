Since you didn't provide the specific source code for your original monolith, I have implemented a high-quality, production-ready version of a Job Queue system following your requested architecture. 

This implementation uses `dataclasses` for clean data modeling, `heapq` for the priority queue, and follows the **Single Responsibility Principle**.

### The New Structure

```text
queue/
├── __init__.py      # Exports: JobQueue, Job
├── core.py          # Job dataclass, basic queue operations
├── retry.py         # Retry logic with exponential backoff
└── priority.py      # Priority queue implementation
```

### 1. `queue/core.py`
*Responsibility: Defines the base data models and the standard FIFO queue.*

```python
import uuid
from dataclasses import dataclass, field
from typing import Callable, Any, List, Tuple, Dict

@dataclass
class Job:
    """Represents a unit of work to be processed."""
    task: Callable
    args: Tuple[Any, ...] = field(default_factory=tuple)
    kwargs: Dict[str, Any] = field(default_factory=dict)
    priority: int = 0
    id: str = field(default_factory= lambda: str(uuid.uuid4()))

    def execute(self) -> Any:
        return self.task(*self.args, **self.kwargs)

class JobQueue:
    """A standard First-In-First-Out (FIFO) job queue."""
    def __init__(self):
        self._jobs: List[Job] = []

    def push(self, job: Job) -> None:
        self._jobs.append(job)

    def pop(self) -> Job:
        if not self._jobs:
            raise IndexError("Pop from empty queue")
        return self._jobs.pop(0)

    def __len__(self) -> int:
        return len(self._jobs)
```

### 2. `queue/priority.py`
*Responsibility: Handles ordering logic based on priority values.*

```python
import heapq
from typing import List
from .core import Job

class PriorityQueue:
    """A Priority Queue where lower numbers represent higher priority."""
    def __init__(self):
        self._queue: List[tuple] = []

    def push(self, job: Job) -> None:
        # We include job.id in the tuple to prevent heapq from 
        # trying to compare Job objects directly if priorities are equal.
        heapq.heappush(self._queue, (job.priority, job.id, job))

    def pop(self) -> Job:
        if not self._queue:
            raise IndexError("Pop from empty queue")
        return heapq.heappop(self._queue)[2]

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
*Responsibility: Pure execution logic and error handling.*

```python
import time
import logging
from .core import Job

logger = logging.getLogger(__name__)

def process_with_retry(
    job: Job, 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """
    Executes a job with exponential backoff.
    Formula: delay = base_delay * (2 ^ attempt)
    """
    attempt = 0
    while attempt < max_retries:
        try:
            return job.execute()
        except Exception as e:
            attempt += 1
            if attempt >= max_retries:
                logger.error(f"Job {job.id} failed after {max_retries} attempts.")
                raise e
            
            delay = base_delay * (2 ** (attempt - 1))
            logger.warning(f"Job {job.id} failed. Retrying in {delay}s...")
            time.sleep(delay)
```

### How to use the new structure:
The user experience remains clean because of the `__init__.py` file.

```python
from queue import Job, JobQueue, PriorityQueue, process_with_retry

def my_task(name):
    print(f"Processing {name}")
    # Simulate failure for retry demo
    if name == "fail":
        raise ValueError("Intentional failure")

# Using Standard Queue
q = JobQueue()
q.push(Job(task=my_task, args=("Task 1",)))
job = q.pop()
process_with_retry(job)

# Using Priority Queue
pq = PriorityQueue()
pq.push(Job(task=my_task, args=("Low Priority",), priority=10))
pq.push(Job(task=my_task, args=("High Priority",), priority=1))

# This will process "High Priority" first
next_job = pq.pop()
process_with_retry(next_job)
```

### Key Refactoring Improvements:
1.  **Encapsulation**: `PriorityQueue` doesn't need to know how `Job` is executed; it only cares about ordering.
2.  **Naming**: Moved the `process_with_retry` into its own module, making it easier to unit test without instantiating a full queue.
3.  **Scalability**: If you want to add a `DistributedQueue` (e.g., using Redis), you can simply add `distributed.py` without touching `core.py`.
4.  **Complexity**: The `PriorityQueue` now handles the "tie-breaker" logic (using `job.id`) which prevents the common `heapq` error of trying to compare two `Job` objects directly.
