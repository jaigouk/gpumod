To refactor this correctly, we will use **relative imports** within the package to ensure that the internal structure doesn't break if the parent folder is renamed.

Here is the refactored structure:

### 1. `queue/core.py`
This file handles the basic data structures and the base queue behavior.

```python
from dataclasses import dataclass, field
from datetime import datetime
from typing import Any, List, Optional
import uuid

@dataclass
class Job:
    payload: Any
    priority: int = 0
    id: str = field(default_factory=lambda: str(uuid.uuid4()))
    created_at: datetime = field(default_factory=datetime.now)

class JobQueue:
    def __init__(self):
        self._jobs: List[Job] = []

    def enqueue(self, job: Job):
        self._jobs.append(job)

    def dequeue(self) -> Optional[Job]:
        return self._jobs.pop(0) if self._jobs else None

    def __len__(self) -> int:
        return len(self._jobs)
```

### 2. `queue/retry.py`
This module isolates the execution logic and error handling.

```python
import time
import logging
from typing import Callable, Any

logging.basicConfig(level=logging.INFO)
logger = logging.getLogger(__name__)

def process_with_retry(
    func: Callable[[], Any], 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """Executes a function with exponential backoff retry logic."""
    retries = 0
    while retries < max_retries:
        try:
            return func()
        except Exception as e:
            retries += 1
            if retries == max_retries:
                logger.error(f"Final attempt failed: {e}")
                raise e
            
            delay = base_delay * (2 ** (retries - 1))
            logger.warning(f"Attempt {retries} failed. Retrying in {delay}s...")
            time.sleep(delay)
```

### 3. `queue/priority.py`
This module handles specific ordering logic, importing the base `Job` from `core`.

```python
import heapq
from typing import List, Optional
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    def __init__(self):
        # We use a list for heapq, but JobQueue structure is maintained
        self._priority_heap: List[tuple[int, Job]] = []

    def enqueue(self, job: Job):
        # heapq is a min-heap, so we negate priority for max-heap behavior
        # Or keep as is if lower number = higher priority
        heapq.heappush(self._priority_heap, (job.priority, job))

    def dequeue(self) -> Optional[Job]:
        if not self._priority_heap:
            return None
        priority, job = heapq.heappop(self._priority_heap)
        return job

    def __len__(self) -> int:
        return len(self._priority_heap)
```

### 4. `queue/__init__.py`
This defines the public API, allowing users to import everything from the top level.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue
from .retry import process_with_retry

__all__ = [
    "Job",
    "JobQueue",
    "PriorityQueue",
    "process_with_retry",
]
```

### Key Changes Explained:

1.  **Encapsulation**: `Job` and `JobQueue` are now in `core.py`. If you add more basic features (like `DelayedJob`), they go there.
2.  **Separation of Concerns**: The retry logic is now a utility in `retry.py`. It doesn't need to know about the `JobQueue` class to work, making it easier to unit test in isolation.
3.  **Inheritance/Composition**: `PriorityQueue` explicitly imports `Job` from `.core`. Using relative imports (`.core`) ensures that the package is portable.
4.  **Clean API**: Because of the imports in `__init__.py`, a user can still use the library exactly as they did before:
    ```python
    from queue import Job, PriorityQueue, process_with_retry
    ```
5.  **Complexity Management**: By splitting these into 4 files, you've reduced the "cognitive load." If a bug exists in the retry timing, you know exactly which file to open.
