### 1. `queue/core.py`
Contains the data models and the standard FIFO (First-In-First-Out) queue logic.

```python
from dataclasses import dataclass, field
from typing import Any, List, Optional

@dataclass
class Job:
    id: str
    payload: Any
    priority: int = 0
    retries: int = 0
    max_retries: int = 3

    def __lt__(self, other: 'Job'):
        # Necessary for PriorityQueue tie-breaking
        return self.priority < other.priority

class JobQueue:
    """A standard FIFO queue for Job objects."""
    def __init__(self):
        self._items: List[Job] = []

    def push(self, job: Job) -> None:
        self._items.append(job)

    def pop(self) -> Optional[Job]:
        if not self._items:
            return None
        return self._items.pop(0)

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
 Contains the specialized logic for priority-based ordering. It depends on `core.py`.

```python
import heapq
from typing import Optional
from .core import Job

class PriorityQueue:
    """A Priority Queue implementation using a min-heap."""
    def __init__(self):
        self._items = []
        self._index = 0  # Tie-breaker for identical priorities

    def push(self, job: Job) -> None:
        # We use an index to ensure stable sorting if priorities are equal
        heapq.heappush(self._items, (job.priority, self._index, job))
        self._index += 1

    def pop(self) -> Optional[Job]:
        if not self._items:
            return None
        return heapq.heappop(self._items)[2]

    def __len__(self) -> int:
        return len(self._items)
```

### 3. `queue/retry.py`
 Contains the functional logic for processing and error handling. It depends on `core.py` for the `Job` definition.

```python
import time
from typing import Callable, Any
from .core import Job

def process_with_retry(
    queue: Any, 
    worker_func: Callable[[Any], None], 
    base_delay: float = 1.0
) -> None:
    """
    Processes jobs from a queue with exponential backoff.
    Works with both JobQueue and PriorityQueue.
    """
    while True:
        job = queue.pop()
        if job is None:
            break

        try:
            worker_func(job.payload)
            print(f"Successfully processed job: {job.id}")
        except Exception as e:
            if job.retries < job.max_retries:
                job.retries += 1
                # Exponential backoff: delay * 2^(retry_count - 1)
                delay = base_delay * (2 ** (job.retries - 1))
                
                print(f"Error processing {job.id}: {e}. "
                      f"Retrying in {delay}s (Attempt {job.retries}/{job.max_retries})")
                
                time.sleep(delay)
                queue.push(job)
            else:
                print(f"Job {job.id} failed permanently after {job.max_retries} retries.")
```

### How to use the new structure:

Because of the `__init__.py` file, the usage remains clean and simple:

```python
from queue import Job, PriorityQueue, process_with_retry

# 1. Define a worker
def my_worker(data):
    if data == "fail":
        raise ValueError("Simulated Failure")
    print(f"Working on {data}")

# 2. Setup data
pq = PriorityQueue()
pq.push(Job(id="1", payload="low priority", priority=10))
pq.push(Job(id="2", payload="fail", priority=1))  # Will retry
pq.push(Job(id="3", payload="high priority", priority=1))

# 3. Run
process_with_retry(pq, my_worker)
```

### Key Refactoring Notes:
1.  **Encapsulation**: `JobQueue` and `PriorityQueue` now share the same `push`/`pop` signature, making `process_with_retry` polymorphic (it doesn't care which queue type you pass in).
2.  **Circular Dependency Prevention**: By placing `Job` in `core.py`, we ensure that `priority.py` and `retry.py` can both import it without creating a loop.
3.  **Complexity**: `PriorityQueue` uses `heapq` for $O(\log n)$ pushes/pops, whereas `JobQueue` uses a list for $O(1)$ pushes and $O(n)$ pops (or $O(1)$ if modified to use `collections.deque`).
