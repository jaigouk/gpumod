### 1. `queue/core.py`
*Responsibility: Defines the data structures and the basic queue interface.*

```python
from dataclasses import dataclass, field
from typing import Any, List, Optional

@dataclass
class Job:
    id: str
    payload: Any
    priority: int = 0
    retry_count: int = 0

    def __lt__(self, other: 'Job') -> bool:
        # Needed for PriorityQueue comparison if not using tuples
        return self.priority < other.priority

class JobQueue:
    """A simple FIFO (First-In-First-Out ) queue."""
    def __init__(self) -> None:
        self._jobs: List[Job] = []

    def enqueue(self, job: Job) -> None:
        self._jobs.append(job)

    def dequeue(self) -> Optional[Job]:
        return self._jobs.pop(0) if self._jobs else None

    def __len__(self) -> int:
        return len(self._jobs)
```

### 2. `queue/priority.py`
*Responsibility: Handles ordered queueing logic.*

```python
import heapq
from typing import Optional
from .core import Job

class PriorityQueue:
    """A priority-based queue using a min-heap."""
    def __init__(self) -> None:
        self._queue: list[tuple[int, int, Job]] = []
        self._counter = 0  # Tie-breaker for same priority

    def enqueue(self, job: Job) -> None:
        # We use a counter to ensure stability (FIFO for same priority)
        # heapq is a min-heap, so lower numbers = higher priority
        heapq.heappush(self._queue, (job.priority, self._counter, job))
        self._counter += 1

    def dequeue(self) -> Optional[Job]:
        if not self._queue:
            return None
        return heapq.heappop(self._queue)[2]

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
*Responsibility: Logic for executing jobs with failure handling.*

```python
import time
import logging
from typing import Callable, Any
from .core import Job

logger = logging.getLogger(__name__)

def process_with_retry(
    job: Job, 
    worker_func: Callable[[Any], Any], 
    max_retries: int = 3
) -> Any:
    """
    Executes a worker function with the job payload.
    Implements exponential backoff: 2^retry_count seconds.
    """
    for attempt in range(max_retries):
        try:
            return worker_func(job.payload)
        except Exception as e:
            job.retry_count += 1
            if job.retry_count >= max_retries:
                logger.error(f"Job {job.id} failed after {max_retries} attempts.")
                raise e
            
            wait_time = 2 ** job.retry_count
            logger.warning(f"Job {job.id} failed. Retrying in {wait_time}s...")
            time.sleep(wait_time)
```

### Example Usage
After refactoring, the user experience remains clean and simple:

```python
from queue import Job, PriorityQueue, process_with_retry

# 1. Define a worker
def send_email(payload):
    print(f"Sending email to: {payload}")
    # Simulate a failure for demo
    if "fail" in payload:
        raise ValueError("Connection error!")

# 2. Setup Queue
pq = PriorityQueue()

# 3. Add Jobs
pq.enqueue(Job(id="1", payload="user@example.com", priority=2))
pq.enqueue(Job(id="2", payload="fail_user@example.com", priority=1)) # Higher priority

# 4. Process
while len(pq) > 0:
    current_job = pq.dequeue()
    if current_job:
        try:
            process_with_retry(current_job, send_email)
        except Exception:
            print(f"Job {current_job.id} permanently failed.")
```

### Key Improvements Made:
1.  **Separation of Concerns**: If you want to change the retry logic (e.g., add jitter), you only touch `retry.py`. If you want to change the storage engine (e.g., Redis), you only touch `core.py`.
2.  **Encapsulation**: `PriorityQueue` uses a private `_queue` and a `_counter` to handle tie-breaking, hiding implementation details from the user.
3.  **Namespace Management**: By using `__init__.py`, the user doesn't need to know the internal file structure to use the library.
4.  **Type Hinting**: Added type hints to ensure better IDE support and fewer runtime bugs.
