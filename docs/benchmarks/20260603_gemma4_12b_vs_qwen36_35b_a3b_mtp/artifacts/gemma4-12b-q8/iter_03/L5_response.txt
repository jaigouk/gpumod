To refactor the monolith into a clean package structure, we will separate the concerns into **Data Modeling** (`core`), **Algorithm Logic** (`priority`), and **Side-effect/Utility Logic** (`retry`).

Here is the refactored structure.

### The Directory Structure
```text
queue/
├── __init__.py      # Public API
├── core.py          # Job dataclass and basic Queue
├── retry.py         # Exponential backoff logic
└── priority.py      # Priority-based Queue
```

---

### 1. `queue/core.py`
Contains the fundamental data structures. By putting `Job` here, we prevent circular imports because both `retry` and `priority` will depend on `core`.

```python
from dataclasses import dataclass, field
from typing import Callable, Any, List, Optional

@dataclass
class Job:
    id: str
    action: Callable[..., Any]
    args: tuple = field(default_factory=tuple)
    kwargs: dict = field(default_factory=dict)
    priority: int = 10
    max_retries: int = 3
    current_attempts: int = 0

    def execute(self) -> Any:
        """Executes the assigned callable."""
        return self.action(*self.args, **self.kwargs)

class JobQueue:
    """A basic FIFO (First-In-First-Out ) Job Queue."""
    def __init__(self):
        self._jobs: List[Job] = []

    def enqueue(self, job: Job) -> None:
        self._jobs.append(job)

    def dequeue(self) -> Optional[Job]:
        return self._jobs.pop(0) if self._jobs else None

    def __len__(self) -> int:
        return len(self._jobs)
```

### 2. `queue/retry.py`
 Handles the "Retry" responsibility. It depends on `core` to know what a `Job` object looks like.

```python
import time
import random
from typing import Optional
from .core import Job

def process_with_retry(job: Job) -> bool:
    """
    Executes a job with exponential backoff.
    Returns True if successful, False if exhausted retries.
    """
    while job.current_attempts <= job.max_retries:
        try:
            job.execute()
            return True
        except Exception as e:
            job.current_attempts += 1
            if job.current_attempts > job.max_retries:
                print(f"Job {job.id} failed after {job.max_retries} retries: {e}")
                break
            
            # Exponential backoff: 2^attempt + jitter
            sleep_time = (2 ** job.current_attempts) + random.uniform(0, 1)
            print(f"Retry {job.current_attempts} for {job.id} in {sleep_time:.2f}s...")
            time.sleep(sleep_time)
            
    return False
```

### 3. `queue/priority.py`
 Handles the priority logic. It uses `heapq` to maintain the priority ordering.

```python
import heapq
from typing import Optional
from .core import Job

class PriorityQueue:
    """A Priority Queue implementation using a min-heap."""
    def __init__(self):
        self._queue: list[tuple[int, int, Job]]] = []
        self._count = 0  # Tie-breaker for equal priorities

    def enqueue(self, job: Job) -> None:
        # We include self._count to handle cases where priorities are equal
        # This prevents the heap from trying to compare two Job objects directly
        heapq.heappush(self._queue, (job.priority, self._count, job))
        self._count += 1

    def dequeue(self) -> Optional[Job]:
        if not self._queue:
            return None
        return heapq.heappop(self._queue)[2]

    def __len__(self) -> int:
        return len(self._queue)
```

 This defines the public interface. Users of your package only need to import from `queue`.

---

### Key Refactoring Improvements:

1.  **Circular Dependency Prevention**: By placing `Job` in `core.py`, both `priority.py` and `retry.py` can import it without creating a loop.
2.  **Single Responsibility Principle (SRP)**:
    *   `core`: Only cares about what a Job *is*.
    *   `priority`: Only cares about *ordering*.
    *   `retry`: Only cares about *error handling/timing*.
3.  **Encapsulation**: The internal list in `PriorityQueue` and `JobQueue` is prefixed with an underscore (`_jobs`), signaling it's private, forcing users to use the `enqueue`/`dequeue` methods.
4.  **Tie-Breaking**: In `priority.py`, I added a `self._count` variable. Without this, if two jobs have the same priority, Python would try to compare the `Job` objects themselves (which would crash because `Job` doesn't have a less-than operator).
5.  **Clean API**: A user can now do this:
    ```python
    from queue import Job, PriorityQueue, process_with_retry

    q = PriorityQueue()
    q.enqueue(Job(id="1", action=lambda: print("Done"), priority=1))
    
    job = q.dequeue()
    if job:
        process_with_retry(job)
    ```
