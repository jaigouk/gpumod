Here is the refactored structure.

### 1. `queue/core.py`
This module handles the basic data structures. By putting `Job` here, we ensure that all other modules can import the base object without creating circular dependencies.

```python
from dataclasses import dataclass, field
from typing import Any
from collections import deque

@dataclass(order=False)
class Job:
    """Represents a unit of work in the system."""
    id: str
    payload: Any
    priority: int = 0
    retries: int = 0

    def __lt__(self, other: 'Job') -> bool:
        # Required for PriorityQueue (heapq) to handle ties in priority
        return self.priority < other.priority

class JobQueue:
    """A basic FIFO (First-In-First-Out) queue for Jobs."""
    def __init__(self):
        self._items: deque[Job] = deque()

    def push(self, job: Job) -> None:
        self._items.append(job)

    def pop(self) -> Job | None:
        return self._items.popleft() if self._items else None

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
This module handles the specialized logic for priority. It imports `Job` from `core`.

```python
import heapq
from typing import List
from .core import Job

class PriorityQueue:
    """A Priority Queue implementation using a binary heap."""
    def __init__(self):
        self._heap: List[tuple[int, Job]] = []

    def push(self, job: Job) -> None:
        # We store as a tuple (priority, job) 
        # heapq uses the first element of the tuple for sorting
        heapq.heappush(self._heap, (job.priority, job))

    def pop(self) -> Job | None:
        if not self._heap:
            return None
        _, job = heapq.heappop(self._heap)
        return job

    def __len__(self) -> int:
        return len(self._heap)
```

### 3. `queue/retry.py`
This module contains the functional logic for execution flow and retries, separated from the data structures.

```python
import time
import random
from typing import Callable, Any
from .core import Job

def process_with_retry(
    func: Callable[[Job], Any], 
    job: Job, 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """
    Executes a function with exponential backoff.
    Formula: base_delay * (2 ** retry_count) + jitter
    """
    attempt = 0
    while attempt <= max_retries:
        try:
            return func(job)
        except Exception as e:
            if attempt == max_retries:
                print(f"Job {job.id} failed after {max_retries} retries.")
                raise e
            
            delay = (base_delay * (2 ** attempt)) + random.uniform(0, 1)
            print(f"Job {job.id} failed. Retrying in {delay:.2f}s...")
            time.sleep(delay)
            attempt += 1
            job.retries = attempt
```

---

### Key Improvements Explained:

1.  **Dependency Flow**: The dependency graph is linear (`retry` and `priority` $\rightarrow$ `core` $\rightarrow$ `__init__`). This prevents circular imports, which is the most common issue when refactoring single files into packages.
2.  **Separation of Concerns**:
    *   `core.py` defines **what** a Job is.
    *   `priority.py` defines **how** to sort Jobs.
    *   `retry.py` defines **how** to execute Jobs reliably.
3.  **Encapsulation**: By using `__all__` in `__init__.py`, you explicitly define the public API. If you add internal helper functions to `core.py` later, they won't be automatically exposed to the user.
4.  **Maintainability**: If you decide to swap the `PriorityQueue` from a `heapq` implementation to a `SortedList` implementation, you only need to modify one file without touching the retry logic or the core Job definition.

### How to use it now:
