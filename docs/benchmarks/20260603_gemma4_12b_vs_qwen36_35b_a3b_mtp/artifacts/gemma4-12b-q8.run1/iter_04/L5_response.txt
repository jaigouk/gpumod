### 1. `queue/core.py`
This file contains the base data structures and the basic FIFO (First-In-First-Out) logic.

```python
from dataclasses import dataclass, field
from typing import Any, List, Optional
import uuid

@dataclass(order=False)
class Job:
    payload: Any
    id: str = field(default_factory=lambda: str(uuid.uuid4()))
    retries: int = 0
    priority: int = 10  # Default priority (lower number = higher priority)

    def __lt__(self, other: 'Job'):
        # Required for PriorityQueue (heapq) to compare Jobs
        return self.priority < other.priority

class JobQueue:
    """A basic FIFO Job Queue."""
    def __init__(self):
        self._queue: List[Job] = []

    def put(self, job: Job) -> None:
        self._queue.append(job)

    def get(self) -> Optional[Job]:
        if not self._queue:
            return None
        return self._queue.pop(0)

    def __len__(self) -> int:
        return len(self._queue)
```

### 2. `queue/priority.py`
This module specializes the queue logic using a min-heap for priority handling.

```python
import heapq
from typing import Optional
from .core import Job

class PriorityQueue:
    """A Priority-based Job Queue using a min-heap."""
    def __init__(self):
        self._queue: list[Job] = []

    def put(self, job: Job) -> None:
        # heapq uses the __lt__ method defined in the Job class
        heapq.heappush(self._queue, job)

    def get(self) -> Optional[Job]:
        if not self._queue:
            return None
        return heapq.heappop(self._queue)

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
This module handles the execution logic and the retry decorator/function.

```python
import time
import random
from typing import Callable
from .core import Job

def process_with_retry(
    job: Job, 
    func: Callable[[Any], Any], 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """
    Executes a function with the job payload, 
    implementing exponential backoff with jitter.
    """
    attempts = 0
    while attempts <= max_retries:
        try:
            return func(job.payload)
        except Exception as e:
            attempts += 1
            if attempts > max_retries:
                print(f"Job {job.id} failed after {max_retries} retries.")
                raise e
            
            # Exponential backoff: base * 2^attempts + random jitter
            delay = (base_delay * (2 ** (attempts - 1))) + random.random()
            print(f"Retrying job {job.id} in {delay:.2f}s... (Attempt {attempts})")
            time.sleep(delay)
```

### Key Changes Explained:

1.  **Encapsulation**: `Job` is now a dataclass in `core.py`. By defining `__lt__` inside `Job`, we allow the `PriorityQueue` to work seamlessly with `heapq` without the queue needing to know the internal details of how jobs are compared.
2.  **Circular Dependency Prevention**: 
    *   `core.py` is the foundation (no internal imports).
    *   `priority.py` and `retry.py` import from `core`.
    *   `__init__.py` imports from everything.
    *   This structure ensures that no module depends on another in a circular loop.
3.  **Public API**: By using `__all__` in `__init__.py`, you provide a clean interface. A user can now do:
    ```python
    from queue import Job, PriorityQueue, process_with_retry
    ```
    instead of having to remember which file `PriorityQueue` lives in.
4.  **SRP (Single Responsibility Principle)**: 
    *   `core`: Data definition and basic list storage.
    *   `priority`: Specialized sorting logic.
    *   `retry`: Time-based execution logic (independent of how jobs are stored).
