### 1. `queue/core.py`
Contains the foundational data structures and the basic linear queue.
```python
from dataclasses import dataclass, field
from typing import Callable, Any, List, Optional

@dataclass
class Job:
    """Represents a unit of work to be processed."""
    id: str
    func: Callable
    args: tuple = field(default_factory=tuple)
    priority: int = 0
    max_retries: int = 3
    current_retry: int = 0

class JobQueue:
    """A basic First-In-First-Out (FIFO) queue for Jobs."""
    def __init__(self):
        self._items: List[Job] = []

    def enqueue(self, job: Job) -> None:
        self._items.append(job)

    def dequeue(self) -> Optional[Job]:
        return self._items.pop(0) if self._items else None

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
Contains the specialized Priority Queue implementation.
```python
import heapq
from typing import Optional
from .core import Job

class PriorityQueue:
    """A priority-based queue where lower priority numbers are processed first."""
    def __init__(self):
        self._queue: list[tuple[int, Job]] = []

    def enqueue(self, job: Job) -> None:
        # heapq is a min-heap, so lower priority numbers come out first
        heapq.heappush(self._queue, (job.priority, job))

    def dequeue(self) -> Optional[Job]:
        if not self._queue:
            return None
        _, job = heapq.heappop(self._queue)
        return job

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
Contains the logic for handling failures and exponential backoff.
```python
import time
from .core import Job

def process_with_retry(job: Job) -> bool:
    """
    Executes a job's function. 
    If it fails, retries using exponential backoff: 2^retry_count.
    """
    while job.current_retry <= job.max_retries:
        try:
            job.func(*job.args)
            return True
        except Exception as e:
            job.current_retry += 1
            if job.current_retry > job.max_retries:
                print(f"Job {job.id} failed permanently after {job.max_retries} retries.")
                break
            
            wait_time = 2 ** job.current_retry
            print(f"Job {job.id} failed (Error: {e}). Retrying in {wait_time}s...")
            time.sleep(wait_time)
            
    return False
```

### Key Improvements Made:

1.  **Encapsulation**: The `JobQueue` and `PriorityQueue` now manage their own internal state (`_items`, `_queue`) making it harder for external code to corrupt the internal lists.
2.  **Separation of Concerns**:
    *   `core.py` defines what a Job *is*.
    *   `priority.py` defines a specific *ordering strategy*.
    *   `retry.py` defines a specific *execution strategy*.
3.  **Namespace Management**: By using `__init__.py`, a user can still do:
    ```python
    from queue import Job, PriorityQueue, process_with_retry
    ```
    This keeps the API clean while keeping the source code organized.
4.  **Type Hinting**: Added PEP 484 type hints to ensure better IDE support and fewer runtime bugs.
5.  **Complexity Management**: By moving the retry logic to its own file, it is now easy to swap `process_with_retry` for an `async_process_with_retry` or a `distributed_process` without touching the queue logic.
