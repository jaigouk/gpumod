To refactor the monolithic file into a clean package, we will use **relative imports** to ensure the package remains portable. 

Here is the refactored structure:

### 1. `queue/core.py`
This file handles the basic data structures and the standard FIFO (First-In-First-Out) queue.

```python
from dataclasses import dataclass
from typing import Any, List, Optional

@dataclass
class Job:
    id: str
    data: Any
    priority: int = 0

class JobQueue:
    """A basic FIFO queue for Job objects."""
    def __init__(self):
        self._jobs: List[Job] = []

    def enqueue(self, job: Job) -> None:
        self._jobs.append(job)

    def dequeue(self) -> Optional[Job]:
        return self._jobs.pop(0) if self._jobs else None

    def __len__(self) -> int:
        return len(self._jobs)
```

### 2. `queue/priority.py`
This file handles the priority logic. It imports the `Job` type from `core`.

```python
import heapq
from typing import List, Optional
from .core import Job

class PriorityQueue:
    """A priority queue where lower priority numbers are processed first."""
    def __init__(self):
        self._queue: List[tuple[int, Job]] = []

    def enqueue(self, job: Job) -> None:
        # We store as a tuple (priority, job) for heapq to sort correctly
        heapq.heappush(self._queue, (job.priority, job))

    def dequeue(self) -> Optional[Job]:
        if not self._queue:
            return None
        # Pop the tuple and return only the Job object
        _, job = heapq.heappop(self._queue)
        return job

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
This file handles the execution logic and the exponential backoff algorithm.

```python
import time
from typing import Callable
from .core import Job

def process_with_retry(
    job: Job, 
    worker_func: Callable[[Job], None], 
    max_retries: int = 3,
    base_delay: float = 1.0
) -> None:
    """
    Executes a worker function on a job. 
    If it fails, retries with exponential backoff.
    """
    retries = 0
    while retries < max_retries:
        try:
            worker_func(job)
            return
        except Exception as e:
            retries += 1
            if retries == max_retries:
                raise e
            
            delay = base_delay * (2 ** (retries - 1))
            print(f"Error processing {job.id}: {e}. Retrying in {delay}s...")
            time.sleep(delay)
```

### 4. `queue/__init__.py`
This file defines the public API, allowing users to import everything directly from `queue`.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue
from .retry import process_with_retry

__all__ = ["Job", "JobQueue", "PriorityQueue", "process_with_retry"]
```

### Key Refactoring Notes:
1.  **Encapsulation**: By moving `Job` to `core.py`, we ensure that both `JobQueue` and `PriorityQueue` have a single source of truth for what a "Job" is.
2.  **Namespace Management**: The `__init__.py` file ensures that the user doesn't have to know the internal file structure. They can simply do:
    ```python
    from queue import Job, JobQueue, PriorityQueue, process_with_retry
    ```
3.  **Single Responsibility**:
    *   `core`: Data definitions and basic list management.
    *   `priority`: Specialized sorting logic (Heapq).
    *   `retry`: Time-based logic and exception handling.
4.  **Relative Imports**: Using `from .core import ...` ensures that if you rename the top-level folder from `queue` to `task_system`, the internal imports won't break.
