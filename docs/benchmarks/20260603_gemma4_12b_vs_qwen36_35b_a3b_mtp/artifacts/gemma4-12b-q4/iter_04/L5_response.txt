To refactor this into a clean package structure, we will use **relative imports** to ensure the package remains portable, and define a clear separation of concerns where `core` holds the data structures, `priority` handles specialized ordering, and `retry` handles the execution logic.

Here is the refactored structure:

### 1. `queue/core.py`
Contains the base data structures and basic list-based queue logic.

```python
from dataclasses import dataclass
from typing import Any, List

@dataclass
class Job:
    id: str
    payload: Any
    priority: int = 0

class JobQueue:
    """A basic FIFO (First-In-First-Out) queue implementation. """
    def __init__(self):
        self._jobs: List[Job] = []

    def push(self, job: Job):
        self._jobs.append(job)

    def pop(self) -> Job:
        if not self._jobs:
            raise IndexError("Pop from empty queue")
        return self._jobs.pop(0)

    def __len__(self):
        return len(self._jobs)
```

### 2. `queue/priority.py`
 Contains the specialized priority logic. It imports `Job` from `core`.

```python
import heapq
from typing import List
from .core import Job

class PriorityQueue:
    """A priority-based queue implementation using a heap."""
    def __init__(self):
        self._jobs: List[tuple] = []

    def push(self, job: Job):
        # We use a tuple (priority, job) so heapq sorts by priority
        # Note: If priorities are equal, it compares the Job objects.
        heapq.heappush(self._jobs, (job.priority, job))

    def pop(self) -> Job:
        if not self._jobs:
            raise IndexError("Pop from empty queue")
        # Return the Job object (index 1 of the tuple)
        return heapq.heappop(self._jobs)[1]

    def __len__(self):
        return len(self._jobs)
```

### 3. `queue/retry.py`
 Contains the logic for retrying operations. It remains decoupled from the specific queue type to remain versatile.

```python
import time
import random
from typing import Callable, Any

def process_with_retry(
    func: Callable[[], Any], 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """
    Executes a function with exponential backoff.
    """
    retries = 0
    while True:
        try:
            return func()
        except Exception as e:
            if retries >= max_retries:
                print(f"Failed after {max_retries} attempts.")
                raise e
            
            # Exponential backoff: delay * 2^retry + jitter
            delay = (base_delay * (2 ** retries)) + random.uniform(0, 1)
            print(f"Attempt {retries + 1} failed. Retrying in {delay:.2f}s...")
            time.sleep(delay)
            retries += 1
```

### 4. `queue/__init__.py`
 This file defines the public API. By importing everything here, users can type `from queue import JobQueue` instead of needing to know the internal file structure.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue
from .retry import process_with_retry

__all__ = ["Job", "JobQueue", "PriorityQueue", "process_with_retry"]
```

### Summary of Changes:
1.  **Encapsulation**: `Job` and `JobQueue` are now clearly defined in `core`, separating the "What" (data) from the "How" (retry logic).
2.  **Specialization**: `PriorityQueue` is moved to its own file. If you later need a `DistributedQueue` or `LRUQueue`, you can simply add new files without bloating `core.py`.
3.  **Dependency Management**: By using `from .core import Job` inside `priority.py`, we ensure that the package can be installed or moved easily while maintaining clear internal links.
4.  **Clean API**: The `__init__.py` acts as a gateway, satisfying the requirement for a clean public API while hiding the internal module complexity.
