### 1. `queue/core.py`
*Responsibility: Data models and basic FIFO queue operations.*

```python
from dataclasses import dataclass, field
from typing import Any, List
from uuid import uuid4

@dataclass(order=False)
class Job:
    data: Any
    id: str = field(default_factory=lambda: str(uuid4()))
    priority: int = 0

class JobQueue:
    """A simple First-In-First-Out queue for Jobs."""
    def __init__(self):
        self._items: List[Job] = []

    def push(self, job: Job) -> None:
        self._items.append(job)

    def pop(self) -> Job:
        if not self._items:
            raise IndexError("Pop from empty queue")
        return self._items.pop(0)

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
*Responsibility: Specialized sorting logic using a heap.*

```python
import heapq
from typing import List
from .core import Job

class PriorityQueue:
    """A Priority Queue where lower numbers indicate higher priority."""
    def __init__(self):
        self._items: List[tuple[int, Job]] = []

    def push(self, job: Job) -> None:
        # We store a tuple (priority, job) so heapq sorts by priority
        heapq.heappush(self._items, (job.priority, job))

    def pop(self) -> Job:
        if not self._items:
            raise IndexError("Pop from empty priority queue")
        _, job = heapq.heappop(self._items)
        return job

    def __len__(self) -> int:
        return len(self._items)
```

### 3. `queue/retry.py`
*Responsibility: Execution logic, error handling, and backoff timing.*

```python
import time
import random
from .core import Job, JobQueue

def process_with_retry(queue: JobQueue, max_retries: int = 3, base_delay: float = 1.0):
    """
    Attempts to pop and process a job from the queue.
    Implements exponential backoff with jitter.
    """
    while True:
        try:
            job = queue.pop()
            print(f"Processing job {job.id}...")
            
            # Simulate actual work logic here
            # If this fails, it raises an exception
            if job.data == "fail":
                raise ValueError("Simulated failure")
                
            print(f"Successfully completed {job.id}")
            break

        except (IndexError, ValueError) as e:
            if max_retries <= 0:
                print(f"Max retries reached. Failed to process.")
                break
            
            # Exponential backoff logic
            delay = (base_delay * (2 ** (3 - max_retries))) + random.uniform(0, 1)
            print(f"Error: {e}. Retrying in {delay:.2f}s...")
            time.sleep(delay)
            max_retries -= 1
```

### Key Changes Made:

1.  **Encapsulation**: Instead of everything being globally accessible in one file, we used `core.py` as the foundation. `priority.py` and `retry.py` now import only what they need from `core`.
2.  **Relative Imports**: Used `from .core import ...` (the dot prefix). This ensures that the package remains portable; you can move the `queue` folder anywhere and it will still work as long as it's treated as a package.
3.  **Circular Dependency Prevention**: By putting the `Job` dataclass in `core.py`, we ensure that `priority.py` (which needs `Job`) and `retry.py` (which needs `JobQueue`) don't create a circular loop.
4.  **Clean Public API**: A user can now do this:
    ```python
    from queue import JobQueue, process_with_retry
    
    q = JobQueue()
    q.push(Job(data="success"))
    process_with_retry(q)
    ```
    They don't need to know the internal file structure (`core`, `retry`, etc.).
5.  **Single Responsibility**:
    *   `core`: Pure data structures.
    *   `priority`: Pure ordering logic.
    *   `retry`: Pure execution/timing logic.
