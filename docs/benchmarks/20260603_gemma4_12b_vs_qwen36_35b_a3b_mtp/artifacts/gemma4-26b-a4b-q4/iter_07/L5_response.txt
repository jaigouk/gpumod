Here is the refactored package structure.

### 1. `queue/core.py`
This module contains the base data models and the fundamental FIFO queue logic. It has no dependencies on other files in the package.

```python
from dataclasses import dataclass, field
from typing import Any, Deque
from collections import deque

@dataclass(order=True)
class Job:
    """
    Represents a unit of work. 
    'order=True' allows Job to be comparable for PriorityQueue.
    """
    priority: int = 10  # Lower number = higher priority
    job_id: str = field(compare=False)
    payload: Any = field(compare=False)

class JobQueue:
    """A standard First-In-First-Out (FIFO) job queue."""
    def __init__(self):
        self._queue: Deque[Job] = deque()

    def push(self, job: Job) -> None:
        self._queue.append(job)

    def pop(self) -> Job:
        if not self._queue:
            raise IndexError("pop from empty queue")
        return self._queue.popleft()

    def __len__(self) -> int:
        return len(self._queue)
```

### 2. `queue/priority.py`
This module implements the specialized priority logic. It imports `Job` and `JobQueue` from `core.py`.

```python
import heapq
from typing import List
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """A queue that retrieves jobs based on their priority level."""
    def __init__(self):
        # We don't call super().__init__() because we are overriding 
        # the underlying storage mechanism from deque to a list (for heapq).
        self._queue: List[Job] = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._queue, job)

    def pop(self) -> Job:
        if not self._queue:
            raise IndexError("pop from empty queue")
        return heapq.heappop(self._queue)

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
This module contains the execution logic. It is decoupled from the specific queue implementation and only cares about the `Job` object.

```python
import time
from typing import Callable
from .core import Job

def process_with_retry(
    func: Callable[[Job], None], 
    job: Job, 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> None:
    """
    Executes a function with a job, applying exponential backoff on failure.
    """
    retries = 0
    while retries < max_retries:
        try:
            func(job)
            return
        except Exception as e:
            retries += 1
            if retries >= max_retries:
                print(f"Job {job.job_id} failed after {max_retries} attempts.")
                raise e
            
            delay = base_delay * (2 ** (retries - 1))
            print(f"Retrying job {job.job_id} in {delay}s... (Attempt {retries})")
            time.sleep(delay)
```

### 4. `queue/__init__.py`
This file acts as the gatekeeper, defining exactly what a user sees when they `import queue`.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue

# We export these to the package level so users can do:
# from queue import Job, JobQueue
__all__ = ["Job", "JobQueue", "PriorityQueue"]
```

### How to use the new structure

Now, instead of one messy file, your user code looks like this:

```python
from queue import Job, PriorityQueue, JobQueue
from queue.retry import process_with_retry

# 1. Using the standard queue
q = JobQueue()
q.push(Job(job_id="1", payload="low priority"))
print(f"FIFO Pop: {q.pop().job_id}")

# 2. Using the priority queue
pq = PriorityQueue()
pq.push(Job(priority=5, job_id="high_id", payload="fast"))
pq.push(Job(priority=1, job_id="critical_id", payload="urgent"))

print(f"Priority Pop: {pq.pop().job_id}") # Outputs: critical_id

# 3. Using retry logic
def unstable_task(job):
    if job.job_id == "critical_id":
        raise ValueError("Boom!")
    print("Task successful")

try:
    process_with_retry(unstable_task, Job(job_id="critical_id", payload="data"))
except ValueError:
    print("Caught final failure.")
```

### Summary of Refactor Benefits:
1.  **Circular Dependency Prevention**: `core.py` is at the bottom of the dependency chain. `priority.py` and `retry.py` depend on `core.py`, but `core.py` depends on nothing.
2.  **Encapsulation**: The user doesn't need to know that `PriorityQueue` uses `heapq` internally; they only interact with the public API.
3.  **Scalability**: If you want to add a `RedisQueue` later, you can just add `queue/redis_queue.py` without touching the retry logic or the core `Job` definition.
