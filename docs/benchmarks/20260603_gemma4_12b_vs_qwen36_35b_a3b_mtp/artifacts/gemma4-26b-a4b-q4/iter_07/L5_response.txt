To refactor this, we will establish a clear hierarchy where `core.py` acts as the foundation, `priority.py` and `retry.py` act as specialized extensions/utilities, and `__init__.py` acts as the gateway for the user.

Here is the refactored package structure.

### 1. `queue/core.py`
This module contains the fundamental data structures. We use `dataclasses` for the `Job` and a standard `collections.deque` for the base `JobQueue`.

```python
from dataclasses import dataclass, field
from typing import Any
from collections import deque

@dataclass(order=True)
class Job:
    """
    Represents a unit of work. 
    'order=True' allows Job to be compared (useful for PriorityQueue).
    """
    priority: int
    job_id: str = field(compare=False)
    payload: Any = field(compare=False)

class JobQueue:
    """A basic FIFO (First-In-First-Out) queue implementation."""
    def __init__(self):
        self._items = deque()

    def push(self, job: Job) -> None:
        self._items.append(job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from empty queue")
        return self._items.popleft()

    def is_empty(self) -> bool:
        return len(self._items) == 0

    def __len__(self) -> int:
        return len(self._items)
```

### 2. `queue/priority.py`
This module specializes the queue logic using Python's `heapq` module. It inherits from `JobQueue` to maintain interface consistency.

```python
import heapq
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """A queue that pops jobs based on priority (lowest number first)."""
    def __init__(self):
        # We override the internal storage to use a list for heapq
        self._items = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._items, job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from empty queue")
        return heapq.heappop(self._items)

    def is_empty(self) -> bool:
        return len(self._items) == 0

    def __len__(self) -> int:
        return len(self._items)
```

### 3. `queue/retry.py`
This module contains the execution logic. By separating this, we ensure that the queue itself doesn't need to know "how" to execute a task, only how to store it.

```python
import time
from typing import Callable
from .core import Job

def process_with_retry(
    job: Job, 
    task_func: Callable[[Job], Any], 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """
    Executes a function with a job, implementing exponential backoff.
    
    :param job: The Job instance to process.
    :param task_func: A function that accepts a Job and performs the work.
    :param max_retries: Number of times to retry after initial failure.
    :param base_delay: The initial delay in seconds.
    """
    attempts = 0
    while attempts <= max_retries:
        try:
            return task_func(job)
        except Exception as e:
            attempts += 1
            if attempts > max_retries:
                print(f"Job {job.job_id} failed after {max_retries} retries.")
                raise e
            
            delay = base_delay * (2 ** (attempts - 1))
            print(f"Job {job.job_id} failed. Retrying in {delay}s... (Attempt {attempts}/{max_retries})")
            time.sleep(delay)
```

### 4. `queue/__init__.py`
This file defines the public API. It allows users to import from `queue` directly rather than navigating the internal file structure.

```python
from .core import Job, JobQueue
from .priority import PriorityQueue

# Define what is available when a user does 'from queue import *'
__all__ = [
    "Job",
    "JobQueue",
    "PriorityQueue"
]
```

### Summary of Improvements
1.  **Single Responsibility**: `core.py` only cares about data; `priority.py` only cares about ordering; `retry.py` only cares about execution logic.
2.  **Encapsulation**: The user interacts with the `queue` package via `__init__.py`, hiding the complexity of the internal modules.
3.  **Extensibility**: If you wanted to add a `DatabaseJobQueue` later, you could simply add `database.py` without touching the retry logic or the base `Job` class.
4.  **Complexity Management**: The `Job` class uses `field(compare=False)` to ensure that `heapq` in the `PriorityQueue` only compares the `priority` integer, preventing errors when comparing complex `payload` objects.
