Here is the refactored package structure.

### 1. `queue/core.py`
This module contains the data models and the base abstraction for a queue. It has no dependencies on retry logic or priority logic.

```python
from dataclasses import dataclass, field
from abc import ABC, abstractmethod
from typing import Any, List

@dataclass(order=True)
class Job:
    """Represents a unit of work."""
    # priority is first for heap comparison compatibility
    priority: int 
    id: str = field(compare=False)
    data: Any = field(compare=False)
    retries: int = field(default=0, compare=False)

class JobQueue(ABC):
    """Abstract Base Class for job queue implementations."""
    
    @abstractmethod
    def push(self, job: Job) -> None:
        pass

    @abstractmethod
    def pop(self) -> Job:
        pass

    @abstractmethod
    def is_empty(self) -> bool:
        pass

    @abstractmethod
    def __len__(self) -> int:
        pass
```

### 2. `queue/priority.py`
This module implements the specific logic for a priority-based queue using Python's `heapq`. It depends on `core.py`.

```python
import heapq
from typing import List
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """A thread-unsafe priority queue implementation using a min-heap."""
    
    def __init__(self):
        self._queue: List[Job] = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._queue, job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from empty queue")
        return heapq.heappop(self._queue)

    def is_empty(self) -> bool:
        return len(self._queue) == 0

    def __len__(self) -> int:
        return len(self._queue)
```

### 3. `queue/retry.py`
This module handles the execution logic and error handling. It is decoupled from the specific queue implementation, requiring only a `Job` object.

```python
import time
import logging
from typing import Callable
from .core import Job

logger = logging.getLogger(__name__)

def process_with_retry(
    job: Job, 
    func: Callable[[Any], Any], 
    max_retries: int = 3, 
    backoff_factor: float = 2.0
) -> Any:
    """
    Executes a function with a job, implementing exponential backoff.
    """
    attempt = 0
    while attempt <= max_retries:
        try:
            return func(job.data)
        except Exception as e:
            attempt += 1
            job.retries = attempt
            
            if attempt > max_retries:
                logger.error(f"Job {job.id} failed after {max_retries} retries.")
                raise e
            
            sleep_time = backoff_factor ** attempt
            logger.warning(f"Job {job.id} failed. Retrying in {sleep_time}s... (Attempt {attempt})")
            time.sleep(sleep_time)
```

### How to use the new package

Now, instead of managing a single messy file, your implementation code looks clean and professional:

```python
from queue import Job, PriorityQueue, process_with_retry

# 1. Setup
q = PriorityQueue()
q.push(Job(priority=2, id="1", data="low priority task"))
q.push(Job(priority=1, id="2", data="urgent task"))

# 2. Define a worker function
def my_worker(data):
    print(f"Processing: {data}")
    if "urgent" not in data:
        raise ValueError("Simulated failure")
    return "Success!"

# 3. Process
while not q.is_empty():
    current_job = q.pop()
    try:
        result = process_with_retry(current_job, my_worker)
        print(f"Result: {result}")
    except Exception:
        print(f"Job {current_job.id} permanently failed.")
```

### Summary of Improvements:
1.  **Single Responsibility:** `core.py` defines *what* a job is; `priority.py` defines *how* jobs are stored; `retry.py` defines *how* jobs are executed.
2.  **Encapsulation:** The user doesn't need to know that `PriorityQueue` uses `heapq` or that `Job` is a `dataclass`. They only interact with the API exposed in `__init__.py`.
3.  **Extensibility:** If you wanted to add a `RedisQueue`, you would simply create `queue/redis_queue.py`, inherit from `JobQueue`, and add it to `__init__.py`. You wouldn't have to touch the retry logic or the Job definition.
