### 1. `queue/core.py`
This module defines the data models and the base queue behavior. It has no internal dependencies.

```python
from dataclasses import dataclass, field
from typing import Any, List

@dataclass(order=True)
class Job:
    """Represents a unit of work."""
    # priority is first so dataclass 'order=True' works with heapq/sorting
    priority: int 
    job_id: str = field(compare=False)
    payload: Any = field(compare=False)

class JobQueue:
    """A standard FIFO (First-In-First-Out) job queue."""
    def __init__(self):
        self._queue: List[Job] = []

    def push(self, job: Job) -> None:
        self._queue.append(job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from empty queue")
        return self._queue.pop(0)

    def is_empty(self) -> bool:
        return len(self._queue) == 0

    def __len__(self) -> int:
        return len(self._queue)
```

### 2. `queue/priority.py`
This module specializes the queue logic using a heap. It depends on `core.py`.

```python
import heapq
from typing import List
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """A queue that pops jobs based on priority (lowest number first)."""
    def __init__(self):
        # We override the internal storage to use a heap-ready list
        self._queue: List[Job] = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._queue, job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from empty priority queue")
        return heapq.heappop(self._queue)

    def is_empty(self) -> bool:
        return len(self._queue) == 0
```

### 3. `queue/retry.py`
This module contains the execution logic. It is decoupled from the specific queue implementation, depending only on the `Job` type.

```python
import time
from typing import Callable
from .core import Job

def process_with_retry(
    job: Job, 
    worker: Callable[[Job], None], 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> None:
    """
    Executes a worker function with exponential backoff.
    """
    retries = 0
    while retries <= max_retries:
        try:
            worker(job)
            return
        except Exception as e:
            retries += 1
            if retries > max_retries:
                print(f"Job {job.job_id} failed after {max_retries} retries.")
                raise e
            
            delay = base_delay * (2 ** (retries - 1))
            print(f"Retrying job {job.job_id} in {delay}s... (Attempt {retries}/{max_retries})")
            time.sleep(delay)
```

### How to use the refactored package

Now, instead of managing one giant file, your implementation code is clean and professional:

```python
from queue import Job, PriorityQueue, process_with_retry

# 1. Setup
pq = PriorityQueue()

# 2. Add jobs (priority 1 is higher than priority 10)
pq.push(Job(priority=10, job_id="low-1", payload="low priority work"))
pq.push(Job(priority=1, job_id="high-1", payload="urgent work"))

# 3. Define a worker that occasionally fails
def my_worker(job):
    if job.job_id == "high-1":
        print(f"Processing {job.job_id}...")
        raise ValueError("Temporary glitch!")
    print(f"Successfully processed {job.job_id}")

# 4. Process
while not pq.is_empty():
    current_job = pq.pop()
    try:
        process_with_retry(current_job, my_worker)
    except Exception:
        print(f"Final failure for {current_job.job_id}")
```

### Key Refactoring Benefits:
1.  **Encapsulation**: If you decide to change the `PriorityQueue` from `heapq` to a different algorithm, you only touch `priority.py`.
2.  **Dependency Management**: `retry.py` doesn't need to know how the queue works; it only needs to know what a `Job` looks like.
3.  **Testability**: You can now write unit tests for `core.py` without triggering the timing logic in `retry.py`.
4.  **Clean API**: The end-user interacts with a flat namespace (`queue.Job`) rather than a nested one (`queue.core.Job`).
