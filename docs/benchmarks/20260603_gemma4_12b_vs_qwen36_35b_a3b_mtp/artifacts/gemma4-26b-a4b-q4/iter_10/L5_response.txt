### 1. `queue/core.py`
This module contains the fundamental data structures. The `Job` uses `order=True` to allow the `PriorityQueue` to compare jobs naturally based on their fields.

```python
from dataclasses import dataclass, field
from typing import Any, Protocol

@dataclass(order=True)
class Job:
    """Represents a unit of work."""
    priority: int  # Lower numbers = higher priority (standard heap behavior)
    id: str = field(compare=False)
    data: Any = field(compare=False)

class JobQueue(Protocol):
    """Interface for queue implementations."""
    def push(self, job: Job) -> None:
        ...

    def pop(self) -> Job:
        ...

    def is_empty(self) -> bool:
        ...
```

### 2. `queue/priority.py`
This module implements the specific behavior of the queue using Python's `heapq`. It depends on `core.py`.

```python
import heapq
from typing import List
from .core import Job, JobQueue

class PriorityJobQueue(JobQueue):
    """A thread-unsafe priority queue implementation using a heap."""
    
    def __init__(self):
        self._storage: List[Job] = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._storage, job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from an empty queue")
        return heapq.heappop(self._storage)

    def is_empty(self) -> bool:
        return len(self._storage) == 0

    def __len__(self) -> int:
        return len(self._storage)
```

### 3. `queue/retry.py`
This module contains the execution logic. It is decoupled from the queue implementation, allowing you to retry any callable.

```python
import time
import random
import logging

logger = logging.getLogger(__name__)

def process_with_retry(
    func, 
    max_retries: int = 3, 
    base_delay: float = 1.0, 
    exponential: bool = True
):
    """
    Executes a function with exponential backoff retry logic.
    """
    retries = 0
    while retries <= max_retries:
        try:
            return func()
        except Exception as e:
            retries += 1
            if retries > max_retries:
                logger.error(f"Max retries reached. Final error: {e}")
                raise e
            
            delay = base_delay * (2 ** (retries - 1) if exponential else 1)
            jitter = random.uniform(0, 0.1 * delay)
            sleep_time = delay + jitter
            
            logger.warning(f"Attempt {retries} failed: {e}. Retrying in {sleep_time:.2f}s...")
            time.sleep(sleep_time)
```

### How to use the new structure

Now that the code is modularized, your implementation code looks much cleaner:

```python
from queue import Job, PriorityJobQueue, process_with_retry

# 1. Setup
queue = PriorityJobQueue()
queue.push(Job(priority=2, id="low-task", data={"payload": "low"}))
queue.push(Job(priority=1, id="high-task", data={"payload": "high"}))

# 2. Define a worker function
def worker_logic():
    job = queue.pop()
    print(f"Processing {job.id}...")
    # Simulate a flaky service
    if job.id == "high-task":
        raise ConnectionError("Server is down!")
    return f"Success: {job.id}"

# 3. Execute with retry logic
try:
    result = process_with_retry(worker_logic, max_retries=2)
    print(result)
except Exception as e:
    print(f"Job failed permanently: {e}")
```

### Key Refactoring Improvements:
1.  **Single Responsibility**: `core.py` only cares about data definitions; `priority.py` only cares about storage mechanics; `retry.py` only cares about execution flow.
2.  **Encapsulation**: The internal `_storage` list in `PriorityJobQueue` is hidden from the user.
3.  **Extensibility**: If you wanted to add a `RedisJobQueue`, you would simply create `queue/redis_queue.py` and add it to `__init__.py` without touching the existing code.
4.  **Dependency Management**: We use relative imports (`from .core import ...`) which makes the `queue` folder a self-contained, portable package.
