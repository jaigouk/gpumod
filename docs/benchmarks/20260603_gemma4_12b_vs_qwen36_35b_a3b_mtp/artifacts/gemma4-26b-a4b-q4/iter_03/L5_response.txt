### 1. `queue/core.py`
This module contains the data models and the abstract base class. It has no dependencies on other files in the package, ensuring a clean foundation.

```python
from dataclasses import dataclass, field
from abc import ABC, abstractmethod
from typing import Any

@dataclass(order=True)
class Job:
    """Represents a unit of work."""
    # priority is first for dataclass(order=True) to work with heapq
    priority: int 
    job_id: str = field(compare=False)
    payload: Any = field(compare=False)

class JobQueue(ABC):
    """Abstract base class defining the interface for all queue types."""
    
    @abstractmethod
    def push(self, job: Job) -> None:
        pass

    @abstractmethod
    def pop(self) -> Job:
        pass

    @abstractmethod
    def is_empty(self) -> bool:
        pass
```

### 2. `queue/priority.py`
This module implements the specific logic for a priority-based queue. It depends on `core.py`.

```python
import heapq
from .core import Job, JobQueue

class PriorityQueue(JobQueue):
    """A FIFO queue that orders jobs by priority (lowest number first)."""
    
    def __init__(self):
        self._storage = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._storage, job)

    def pop(self) -> Job:
        if self.is_empty():
            raise IndexError("pop from empty queue")
        return heapq.heappop(self._storage)

    def is_empty(self) -> bool:
        return len(self._storage) == 0
```

### 3. `queue/retry.py`
This module contains the execution logic. It is decoupled from the queue implementation itself, focusing only on the lifecycle of a single job.

```python
import time
import logging
from .core import Job

logger = logging.getLogger(__name__)

def process_with_retry(job: Job, task_func, max_retries: int = 3, backoff_factor: float = 2.0):
    """
    Executes a function with the job payload using exponential backoff.
    """
    retries = 0
    delay = 1.0

    while retries <= max_retries:
        try:
            return task_func(job.payload)
        except Exception as e:
            retries += 1
            if retries > max_retries:
                logger.error(f"Job {job.job_id} failed after {max_retries} retries.")
                raise e
            
            logger.warning(f"Job {job.job_id} failed. Retrying in {delay}s... ({retries}/{max_retries})")
            time.sleep(delay)
            delay *= backoff_factor
```

This file acts as the public gateway. It hides the internal file structure from the user, allowing them to import from `queue` directly rather than `queue.core`.

### How to use the refactored package

Now, instead of managing a single massive file, a consumer of your library uses it cleanly like this:

```python
from queue import Job, JobQueue
from queue.priority import PriorityQueue
from queue.retry import process_with_retry

# 1. Setup
queue: JobQueue = PriorityQueue()

# 2. Add Jobs (Priority 1 is higher than Priority 10)
queue.push(Job(priority=10, job_id="low-pri", payload="low-value-work"))
queue.push(Job(priority=1, job_id="high-pri", payload="critical-work"))

# 3. Define a task
def my_task(data):
    print(f"Executing: {data}")
    return True

# 4. Process
while not queue.is_empty():
    current_job = queue.pop()
    process_with_retry(current_job, my_task)
```

4.  **Extensibility**: If you want to add a `RedisQueue`, you simply add `queue/redis_queue.py` without touching the retry logic or the core models.
