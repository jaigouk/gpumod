To refactor this into a professional package structure, we will use relative imports to ensure the package is portable and a clear separation of concerns.

Here is the refactored code.

### 1. `queue/core.py`
This module defines the data models and the base logic for the queue. It has no dependencies on other modules in the package.

```python
from dataclasses import dataclass, field
from typing import Any, List, Optional

@dataclass(order=False)
class Job:
    """Represents a unit of work."""
    id: str
    payload: Any
    priority: int = 0

    def __lt__(self, other: 'Job') -> bool:
        # Required for PriorityQueue (heapq) to compare jobs
        return self.priority < other.priority

class JobQueue:
    """A basic FIFO (First-In-First-Out) job queue."""
    def __init__(self):
        self._jobs: List[Job] = []

    def enqueue(self, job: Job) -> None:
        self._jobs.append(job)

    def dequeue(self) -> Optional[Job]:
        return self._jobs.pop(0) if self._jobs else None

    def __len__(self) -> int:
        return len(self._jobs)
```

### 2. `queue/priority.py`
This module implements the specialized priority logic. It inherits from `JobQueue` but overrides the storage mechanism using a heap.

```python
import heapq
from typing import Optional
from .core import JobQueue, Job

class PriorityQueue(JobQueue):
    """A queue that processes jobs based on priority (lower number = higher priority)."""
    def __init__(self):
        self._jobs = []  # Used by heapq

    def enqueue(self, job: Job) -> None:
        heapq.heappush(self._jobs, job)

    def dequeue(self) -> Optional[Job]:
        return heapq.heappop(self._jobs) if self._jobs else None

    def __len__(self) -> int:
        return len(self._jobs)
```

### 3. `queue/retry.py`
This module handles execution logic. It is decoupled from the queue storage, allowing it to work with any job-executing function.

```python
import time
import logging
from .core import Job

logger = logging.getLogger(__name__)

def process_with_retry(
    job_func, 
    job: Job, 
    max_retries: int = 3, 
    base_delay: float = 1.0
):
    """
    Executes a function with a job, implementing exponential backoff.
    
    :param job_func: A callable that accepts a Job and returns a result.
    :param job: The Job instance to process.
    :param max_retries: Number of times to retry after failure.
    :param base_delay: Initial delay in seconds.
    """
    retries = 0
    while retries <= max_retries:
        try:
            return job_func(job)
        except Exception as e:
            retries += 1
            if retries > max_retries:
                logger.error(f"Job {job.id} failed after {max_retries} retries.")
                raise e
            
            delay = base_delay * (2 ** (retries - 1))
            logger.warning(f"Job {job.id} failed. Retrying in {delay}s... (Attempt {retries}/{max_retries})")
            time.sleep(delay)
```

### 4. `queue/__init__.py`
This file defines the public API. By importing specific classes here, users can use `from queue import Job, JobQueue` without needing to know the internal file structure.

```python

```

### Summary of Refactoring Improvements:
1.  **Encapsulation**: `JobQueue` manages a list, while `PriorityQueue` manages a heap, but they share the same interface.
2.  **Decoupling**: `process_with_retry` doesn't care *how* the job was stored; it only requires a `Job` object.
3.  **Maintainability**: If you want to add a `DatabaseQueue` later, you just add `database.py` without touching the retry or priority logic.
4.  **Complexity Management**: `core.py` remains lightweight, making it easy to understand the base data models.
