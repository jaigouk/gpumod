### 1. `queue/core.py`
This module defines the data models and the primary interface for the queue. We use a `Protocol` (Interface) for the backend to avoid circular imports between `core` and `priority`.

```python
from dataclasses import dataclass, field
from typing import Any, Protocol

@dataclass(order=True)
class Job:
    """Represents a unit of work with a priority."""
    priority: int
    data: Any = field(compare=False)

class QueueBackend(Protocol):
    """Structural type for queue implementations."""
    def push(self, job: Job) -> None: ...
    def pop(self) -> Job: ...
    def empty(self) -> bool: ...

class JobQueue:
    """The high-level interface used by the application."""
    def __init__(self, backend: QueueBackend):
        self.backend = backend

    def add(self, job: Job) -> None:
        self.backend.push(job)

    def get(self) -> Job:
        return self.backend.pop()

    def is_empty(self) -> bool:
        return self.backend.empty()
```

### 2. `queue/priority.py`
This module handles the specific implementation of the priority logic. It imports `Job` and the `QueueBackend` protocol from `core`.

```python
import heapq
from .core import Job, QueueBackend

class PriorityQueue(QueueBackend):
    """A min-heap based priority queue implementation."""
    def __init__(self):
        self._items = []

    def push(self, job: Job) -> None:
        heapq.heappush(self._items, job)

    def pop(self) -> Job:
        if self.empty():
            raise IndexError("pop from empty queue")
        return heapq.heappop(self._items)

    def empty(self) -> bool:
        return len(self._items) == 0
```

### 3. `queue/retry.py`
This module is dedicated to execution logic. By separating this, you can test retry logic without needing to instantiate a full queue.

```python
import time
from typing import Callable
from .core import Job

def process_with_retry(
    job_func: Callable[[Any], Any], 
    job: Job, 
    max_retries: int = 3, 
    base_delay: float = 1.0
) -> Any:
    """Executes a function with exponential backoff."""
    retries = 0
    while retries < max_retries:
        try:
            return job_func(job.data)
        except Exception as e:
            retries += 1
            if retries >= max_retries:
                raise e
            
            delay = base_delay * (2 ** (retries - 1))
            print(f"Attempt {retries} failed. Retrying in {delay}s...")
            time.sleep(delay)
```

### How to use the new structure

The beauty of this refactor is that the end-user experience remains clean, but the internal code is now decoupled.

```python
from queue import Job, JobQueue
from queue.priority import PriorityQueue
from queue.retry import process_with_retry

# 1. Setup (Dependency Injection)
backend = PriorityQueue()
queue = JobQueue(backend=backend)

# 2. Add Jobs
queue.add(Job(priority=2, data="low priority task"))
queue.add(Job(priority=1, data="critical task"))

# 3. Process
def my_task(data):
    if data == "critical task":
        raise ValueError("Simulated Failure")
    print(f"Executing: {data}")
    return True

job = queue.get()
try:
    process_with_retry(my_task, job)
except Exception as e:
    print(f"Job failed after retries: {e}")
```

### Key Refactoring Improvements:
1.  **Eliminated Circular Dependencies**: By using a `Protocol` in `core.py`, `core` doesn't need to know `PriorityQueue` exists, but `PriorityQueue` still knows how to interact with `Job`.
2.  **Dependency Injection**: `JobQueue` now accepts *any* backend that follows the `QueueBackend` protocol. You could easily add a `RedisQueue` or `SqliteQueue` in a new file without touching `core.py`.
3.  **Encapsulation**: The `__init__.py` file acts as a gatekeeper. The user only sees `Job` and `JobQueue`, reducing cognitive load.
4.  **Testability**: You can now write unit tests for `retry.py` by passing in a mock function, without ever needing to touch the queue logic.
