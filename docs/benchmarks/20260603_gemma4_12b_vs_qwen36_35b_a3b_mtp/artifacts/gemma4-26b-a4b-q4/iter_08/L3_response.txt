*   Goal: Implement a priority-based job scheduling system for a `JobQueue`.
    *   Requirement 1: `add_job(name, data, priority=0)` where priority is optional.
    *   Requirement 2: Higher priority (larger number) processed first.
    *   Requirement 3: FIFO for same priority.
    *   Requirement 4: `get_next_job() -> tuple[str, dict] | None` returns the highest priority job.
    *   Priority Levels: 0 (Normal), 1 (High), 2 (Critical).

    *   The standard way to implement priority queues in Python is using the `heapq` module.
    *   `heapq` is a min-heap. To make it a max-heap for priority (so higher number comes first), we can store the priority as a negative value.
    *   Requirement 3 (FIFO for same priority) is tricky with a simple heap if we only use priority. To maintain order, we need a "tie-breaker". A common trick is to use a sequence counter.
    *   The heap element should be: `(-priority, sequence_number, job_name, job_data)`.
        *   `-priority`: Higher priority numbers become smaller, so they come out first in a min-heap.
        *   `sequence_number`: Ensures FIFO for same priority.
        *   `job_name` and `job_data`: The payload.

    *   Class: `JobQueue`.
    *   `__init__`: Initialize an empty list `_heap` and a counter `_count`.
    *   `add_job(name, data, priority=0)`:
        *   `_count += 1`
        *   `heapq.heappush(_heap, (-priority, _count, name, data))`
    *   `get_next_job()`:
        *   If heap is empty, return `None`.
        *   `pop` from heap.
        *   Return `(name, data)`.

    *   `heapq.heappop` returns the smallest element.
    *   With `(-priority, sequence_count, name, data)`:
        *   Smallest `-priority` means highest actual `priority`. (Correct)
        *   If `-priority` is equal, smallest `sequence_count` means it was added earlier. (Correct, satisfies FIFO)

    ```python
    import heapq

    class JobQueue:
        def __init__(self):
            self._heap = []
            self._count = 0

        def add_job(self, name: str, data: dict, priority: int = 0):
            # We use -priority because heapq is a min-heap,
            # but we want higher priority values to come out first.
            # We use self._count to ensure FIFO for same priority.
            heapq.heappush(self._heap, (-priority, self._count, name, data))
            self._count += 1

        def get_next_job(self) -> tuple[str, dict] | None:
            if not self._heap:
                return None
            # Pop the smallest element (highest priority, lowest count)
            _, _, name, data = heapq.heappop(self._heap)
            return (name, data)
    ```

```python
import heapq

class JobQueue:
    def __init__(self):
        self._heap = []
        self._count = 0

    def add_job(self, name: str, data: dict, priority: int = 0) -> None:
        # heapq is a min-heap. To process higher priority values first, 
        # we store priority as a negative number.
        # self._count acts as a tie-breaker to ensure FIFO for same priority.
        heapq.heappush(self._heap, (-priority, self._count, name, data))
        self._count += 1

    def get_next_job(self) -> tuple[str, dict] | None:
        if not self._heap:
            return None
        
        # Pop the element with the lowest value:
        # 1. Lowest negative priority (highest actual priority)
        # 2. Lowest count (earliest added)
        _, _, name, data = heapq.heappop(self._heap)
        return (name, data)
```
