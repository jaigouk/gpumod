Thinking Process:

1.  **Understand the Goal:** Implement a job scheduling system that prioritizes jobs based on an integer priority level (0=Normal, 1=High, 2=Critical). Jobs with higher priority go first. Ties in priority maintain FIFO order.

2.  **Data Structure Choice:**
    *   A standard `list` or `deque` might be inefficient for frequent priority sorting.
    *   A `heapq` (min-heap or max-heap) is ideal for priority queues.
    *   Since we need:
        a) Priority ordering (higher number means higher priority).
        b) FIFO tie-breaking (if priorities are equal).

3.  **Priority Handling in Heaps (Python `heapq`):**
    *   `heapq` is a *min-heap*. To simulate a max-heap (higher numbers first), we store the negative of the priority.
    *   To handle tie-breaking (FIFO), the tuple stored in the heap must be structured such that the next element in the tuple determines the tie-break.
    *   Structure: `(-priority, sequence_number, job_data)`

4.  **Implementation Details:**
    *   Need a counter for sequence numbers to ensure FIFO for same priorities.
    *   Need a class (`JobQueue`) to encapsulate the logic.

5.  **Class Structure (`JobQueue`):**
    *   `__init__`: Initialize the storage (a list or heap).
    *   `add_job(name: str, data: dict, priority: int = 0)`: Accepts the job and priority. Needs to manage the insertion order/heap structure.
    *   `get_next_job()`: Removes and returns the highest priority job.

6.  **Refining `add_job`:**
    *   When adding, we need to store the job's name, data, and priority.
    *   The tie-breaker needs to be handled carefully. If we use `(priority, insertion_index)`, a lower index means FIFO.

    *   *Self-Correction on Heap Logic:*
        *   Priority 2 (Critical) > Priority 1 (High) > Priority 0 (Normal).
        *   We want the smallest element in the heap to represent the *most* urgent job.
        *   If we use `(-priority)`, priority 2 becomes -2. Priority 1 becomes -1. Priority 0 becomes 0. `-2` is smaller than `-1`, which is smaller than `0`. This works for primary ordering.
        *   If priorities are equal (e.g., both 1), we need the one added earlier first.
        *   If we store `(priority, sequence_number, job_data)`, the minimum element will be (0, 0, ...). But since 0 is lowest priority, we'd need a custom comparison.
        *   *Standard Priority Queue approach:* Store `(-priority, sequence_number, job_data)`.

import heapq

class JobQueue:
    def __init__(self):
        # The heap will store tuples of: (-priority, sequence_index, job_data)
        self._queue = []
        self._sequence_counter = 0

    def add_job(self, name: str, data: dict, priority: int = 0):
        # Convert priority to negative because heapq is a min-heap,
        # and we want higher priority numbers (e.g., 2) to come out first.
        neg_priority = -priority
        
        # Push the tuple onto the heap. 
        # Using neg_priority ensures higher priority is treated as smaller in the heap.
        # Sequence counter ensures FIFO for jobs with the same priority.
        entry = (neg_priority, self._sequence_counter, name, data)
        heapq.heappush(self._queue, entry)
        self._sequence_counter += 1

    def get_next_job(self) -> tuple[str, dict] | None:
        if not self._queue:
            return None
        
        # heappop retrieves the smallest element. 
        # This corresponds to the highest negative priority (i.e., highest positive priority).
        neg_priority, _, name, data = heapq.heappop(self._queue)
        
        return name, data

if __name__ == '__main__':
