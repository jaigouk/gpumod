1.  **Understand the Goal:** Implement a priority-based job scheduler/queue in Python.
    *   Jobs need a name (string) and data (dict).
    *   Priority levels: 0 (Normal), 1 (High), 2 (Critical).
    *   Scheduling rule: Higher priority number means higher priority (2 > 1 > 0).
    *   Tie-breaker: FIFO (First-In-First-Out) for jobs with the same priority.
    *   Interface requirements: `add_job(name, data, priority=0)` and `get_next_job()`.

2.  **Choose Data Structure:** A standard queue (like `collections.deque`) is for FIFO. A standard heap is good for priority, but Python's `heapq` implements a min-heap. To get the *highest* priority (P=2) first, I need the structure to naturally put the largest priority at the top.

    *   *Approach A (Manual Sort/List):* Use a list and sort it every time `get_next_job` is called, or maintain a sorted list. This is $O(N \log N)$ or $O(N)$ for insertion/deletion depending on implementation.
    *   *Approach B (Priority Queue using `heapq`):* Python's `heapq` is a min-heap. If I store `(priority, insertion_index, job_data)`, it will sort by priority first.
        *   Lower priority values are extracted first. If we want *higher* priority numbers to be extracted first, I should store the negative priority or adjust the extraction logic.
        *   If P=2 is Critical, and P=0 is Normal. We want 2 before 0.
        *   If I use `(priority, index)`, Python sorts by `priority` ascending.
        *   If I use `-priority`, then -2 (Critical) comes before -1 (High) and -0 (Normal).
        *   Tie-breaker: FIFO. I need a unique identifier for insertion order.

3.  **Implementation Details (Using `heapq` - Approach B):**

    *   The internal structure will be a list used as a heap.
    *   Job item format: `(priority, arrival_time/counter, job_name, job_data)`.
    *   Since we need FIFO for ties, the counter must be strictly increasing with each insertion.

    *   `__init__`: Initialize an empty list (`self.tasks`) and a counter (`self.counter`).

    *   `add_job(name, data, priority)`:
        *   Increment counter.
        *   Push `(priority, self.counter, name, data)` onto the heap.

    *   `get_next_job()`:
        *   Check if the heap is empty.
        *   If not empty, pop the root (min element).
        *   Return `(name, data)`.

4.  **Code Structure Refinement:**

    *   Define `JobQueue` class.
    *   Handle the priority numbers (0, 1, 2).

    *Self-Correction on Tie-breaking:* If I use `(priority, counter)`, and two jobs have `priority=1`:
    - Job A: (1, 1)
    - Job B: (1, 2)
    The heap will extract Job A first because 1 < 2. This correctly maintains FIFO for equal priorities.

    *Self-Correction on Priority interpretation:* The prompt states: "Higher priority jobs should be processed before lower priority jobs".
    Jobs: P=2 (Critical), P=1 (High), P=0 (Normal).
    If we use `heapq` (min-heap):
    1. Priority is the first element.
    2. Min-heap extracts the smallest value first.
    3. If we store `priority=2`, `priority=1`, `priority=0`.
    4. The smallest value is 0. This puts Normal jobs first. This is WRONG.

    *Revised Plan:* To get P=2 first, we must invert the priority sorting.
    Store as `(-priority, counter, name, data)`.
    - P=2 becomes -2.
    - P=1 becomes -1.
    - P=0 becomes 0.
    Smallest values first: -2, -1, 0. This correctly extracts Critical (P=2) then High (P=1) then Normal (P=0).

    *Refining `add_job` with the negative priority.*

```python
import heapq

class JobQueue:
    def __init__(self):
        # tasks stores tuples: (-priority, arrival_index, job_name, job_data)
        self.tasks = []
        self.arrival_index = 0

    def add_job(self, name: str, data: dict, priority: int = 0):
        # Use negative priority to make a max-priority queue using min-heap logic
        heapq.heappush(self.tasks, (-priority, self.arrival_index, name, data))
        self.arrival_index += 1

    def get_next_job(self) -> tuple[str, dict] | None:
        if not self.tasks:
            return None

        # Pop the smallest element (which corresponds to the highest priority)
        # Structure of popped item: (-priority, arrival_index, name, data)
        _, _, name, data = heapq.heappop(self.tasks)
        
        return name, data
```
