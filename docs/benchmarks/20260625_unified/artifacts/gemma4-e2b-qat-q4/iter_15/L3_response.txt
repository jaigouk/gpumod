*   **Goal:** Implement a priority-based job scheduling queue.
*   **Priorities:** 0 (Normal), 1 (High), 2 (Critical). Higher number means higher priority.
*   **Tie-breaking:** FIFO for jobs with the same priority.
*   **Function 1: `add_job(name, metadata, priority)`:** Needs to add jobs to the internal structure.
*   **Function 2: `get_next_job()`:** Needs to retrieve the job with the highest priority (highest number).
*   **Internal Structure:** A heap or a sorted list. Since the requirements emphasize priority first, and then FIFO for ties, a structure that sorts by `(priority, insertion_order)` is ideal. A standard Python list or `heapq` can work.

    *   A simple list of tuples: `[(priority, insertion_index, name, metadata)]` sorted ascendingly? No, we want highest priority first.
    *   If we use a Min-Heap, we need to store `-priority`.

    *   Let's consider the sorting keys: `(priority, insertion_index)`. Since we want higher numbers first, we can sort by `(-priority, insertion_index)`.

*   **Job Structure:** A dictionary or a class/tuple containing the name and metadata. Let's keep it simple and use a dictionary for metadata and the priority score for sorting.

*   **Implementation details for `get_next_job()`:**
    *   Check if the queue is empty.
    *   If using a sorted list: pop the first element.

Let's define the class.

1. Initialize `self.queue` (list of job tuples/objects).
2. `add_job`: Store `(priority, index, name, metadata)`.
3. `get_next_job`: Sort the list based on `priority` descending. Return the first one.

*Refinement on sorting:* To ensure FIFO for the same priority, we need a stable sort.
If we store `(priority, insertion_time, name, metadata)`.
When sorting: `key = (-priority, insertion_time)`. Sorting ascendingly on this key will put highest priority (most negative -priority) first.

Let's use a simpler structure:
Store jobs as dictionaries: `{"priority": P, "name": N, "meta": M}`.

When sorting: Sort by `priority` descending. If priorities are equal, rely on insertion order (which can be tracked by a counter).

*Self-Correction:* The requirement implies `priority=2` (Critical) > `priority=1` (High) > `priority=0` (Normal). Higher number = Higher priority.

```python
class JobQueue:
    def __init__(self):
        # Store jobs as (priority, insertion_index, job_data)
        self._jobs = []
        self._counter = 0

    def add_job(self, name: str, metadata: dict, priority: int = 0):
        # Priority handling: Higher number = higher priority.
        # To ensure correct sorting, we store the negative priority 
        # (if using standard Min-Heap) or sort by priority descending.
        
        # We will store: (priority, insertion_index, name, metadata)
        self._jobs.append((priority, self._counter, name, metadata))
        self._counter += 1

    def get_next_job(self) -> tuple[str, dict] | None:
        if not self._jobs:
            return None
        
        # Sort criteria:
        # 1. Highest priority first (descending priority)
        # 2. FIFO for ties (ascending insertion index)
        
        # Sort by (-priority, insertion_index)
        self._jobs.sort(key=lambda x: (-x[0], x[1]))
        
        # Return name and metadata
        priority, index, name, metadata = self._jobs.pop(0)
        return name, metadata
```
